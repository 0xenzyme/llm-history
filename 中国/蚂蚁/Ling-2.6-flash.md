# Ling-2.6-flash

## 基本信息

**2026-04-22**，蚂蚁百灵正式推出 **Ling-2.6-flash**：总参数 **1040 亿**、激活参数 **74 亿**，采用**混合线性架构**的高度稀疏化 MoE 设计，并通过 API 开放；**2026-04-29 正式开源**。

发布前一周，该模型曾以 **"Elephant Alpha"** 为名在 OpenRouter 平台匿名测试，调用量快速上升——蚂蚁延续了"先匿名上线、后认领"的发布惯例。

## 主打：Token 效率

Ling-2.6-flash 的核心卖点是 **Token Efficiency（Token 效率）**——在保持竞争力智能水平的同时，更快、更省，更适合大规模真实应用。

| 指标 | 数值 |
|---|---|
| 架构 | 混合线性 MoE（总 104B / 激活 7.4B） |
| 推理速度（4 卡 H20） | 最快 **340 tokens/s**，稳定输出 215 tokens/s |
| Prefill 吞吐 | **Nemotron-3-Super 的 2.2 倍** |
| AA 评测 Token 消耗 | 约 **1500 万 output tokens** 取得 **26 分**智能指数，约为部分同类模型的**十分之一** |
| 定价 | **$0.1 / 百万 token** |
| 日均调用 | **1000 亿**级别 Token |

Agent 场景定向增强：在 **BFCL-V4、τ²-bench（TAU2-bench）、SWE-bench Verified** 等基准上位于同尺寸模型前列。

## 为什么"Token 效率"是蚂蚁的核心命题

灵光的"闪应用"要**30 秒内生成可交互、可编辑、可分享的完整应用**，背后是前端 HTML/CSS/JS + 后端逻辑 + 模型调用 + 数据存储的完整代码。相比纯文本输出，**代码膨胀率约 5–6 倍**——同样的用户请求，Token 消耗是普通对话的数倍，且要求高速生成、代码不能出错。

这决定了蚂蚁的基座必须优先优化"单位智能的 Token 成本"，而不是单点跑分。Ling-2.6-flash 是这条思路最清晰的一次产品化。

混合线性架构（1:7 MLA + **Lightning Linear Attention**）是这一代共同的技术底座：在 32K 以上长生成场景中，**访存规模降低 10 倍以上、生成吞吐提升 3 倍以上**。

## 代际意义

- **把"成本"做成一等竞争维度**：在 2026 年"模型开源 + 芯片适配 + API 降价"的三重共振中，Ling-2.6-flash 用 $0.1/M 与"十分之一 Token 消耗"把性价比推到了明确可比的层面。
- **Agent 场景的定向优化**：不再以通用跑分为唯一指标，而是针对工具调用、长程任务做专门增强——这与灵光、CatPaw 一类"交付成果"型产品的需求一致。
- **匿名 → 认领的发布范式**：与美团 LongCat-2.0（"Owl Alpha"）相同，蚂蚁用匿名上线换取真实的第三方调用反馈，再公开身份；这是 2026 年中国厂商常见的验证手段。

## 备注

- **匿名代号**：Ling-2.6-flash = "**Elephant Alpha**"，与美团的 "Owl Alpha"（LongCat-2.0-Preview）属同一时期同一种做法，不要混淆。
- **AA 26 分口径**：该分数来自 Artificial Analysis 智能指数的特定版本，与其他模型的分数（如 MiMo-V2.6-Pro 的 46 分 v4.3.2）**不可直接横比**。
- **速度条件**：340 tokens/s 为 4 卡 H20 环境下的最快值，稳定输出为 215 tokens/s，引用时应注明条件。
